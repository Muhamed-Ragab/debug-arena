🔁 Request Pipeline

Step-by-step lifecycle of an inbound HTTP request through the application stack. Click any step to see implementation detail.

1
Browser sends a request to the Next.js App Router.
▼
The application serves English-only UI routes, API routes, and server actions.
2
Next.js Proxy checks session and route access.
⚙️ Core Middleware ▼
Protected routes redirect anonymous users; admin routes require an admin role.
3
Route or server action validates input.
▼
Zod schemas and next-safe-action clients validate server action inputs and outputs.
4
Feature service calls its repository.
🔧 Core Services ▼
Service factories receive repositories through dependency injection.
5
Repository reads or writes PostgreSQL through Drizzle.
▼
The database stores users, categories, challenges, submissions, and related records.
6
The route or action returns its client-visible response.
▼
Application API routes use the standard envelope; better-auth endpoints retain their native response contract.
⚠ Exception / Error Flow
click to expand

When an exception is thrown at any layer, the following error handling chain is invoked instead of the normal response path.

1
Input validation returns a typed action or API error.
2
Feature services sanitize unexpected failures at their boundary.
3
API routes return the standard success/data/error envelope; better-auth owns its endpoint contract.
4
The UI renders an English error state and can retry where appropriate.
🔒 Scope & Isolation

User-scoped database policies and queries isolate private profile and submission data.
